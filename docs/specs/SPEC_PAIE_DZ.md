# مواصفة حساب كشف الراتب — الجزائر (نسخة 2026)
### وثيقة مرجعية موجّهة للمبرمج (Claude Code)

> **نطاق التغطية:** العامل الأجير في الحالة العادية (`STANDARD`) فقط. الأنظمة الخاصة بالمتقاعدين وذوي الإعاقة **خارج نطاق هذه المواصفة** ولا تُبرمَج.

> **قاعدة ذهبية:** كل رقم قانوني في هذه الوثيقة يجب أن يكون في **ملف إعدادات خارجي مؤرَّخ** (`config/params_2026.json`)، ولا يُكتب أبداً داخل الكود (no hardcoded values). قوانين المالية تتغيّر كل سنة، والبرنامج يجب أن يحسب كشوف سنوات سابقة بمعاملات تلك السنة.

## 1.2 طبقتا الإعدادات — فصل إلزامي

قواعد الأجور في الجزائر نوعان، لهما دورة حياة مختلفة تماماً. خلطهما في ملف واحد هو أخطر خطأ معماري في برامج الأجور.

| | الطبقة القانونية | طبقة الاتفاقية |
|---|---|---|
| **أين** | `params_<سنة>.json` | جدول `convention` لكل شركة في قاعدة البيانات |
| **يشمل** | نسبة CNAS، سلم IRG، التخفيض، SNMG، الحد الأدنى للساعة الإضافية | قاعدة IEP، قاعدة PRI، تنسيب السلة والنقل، معاملات الساعات الإضافية الفعلية |
| **يتغيّر بـ** | قانون المالية | عقد أو اتفاقية جماعية |
| **موحّد؟** | نعم، لكل الجزائر | لا، يختلف من شركة لأخرى |
| **المخالفة تعني** | تصريحاً جبائياً خاطئاً | نزاعاً مع الزبون أو العامل |

⚠️ **لا يوجد «صواب وخطأ» في الطبقة الثانية.** رُصد في كشفين حقيقيين تطبيقان مختلفان لقاعدة IEP، وكلاهما سليم — كل مؤسسة تطبّق اتفاقيتها. تثبيت أحدهما في المحرّك يعني الخطأ مع نصف الزبناء مهما كان الاختيار.

### 1.2.1 مخطط ملف الاتفاقية

```json
{
  "convention_version": 1,
  "confirme_par_utilisateur": false,
  "base_iep": "SAL_BASE_BRUT",
  "base_pri": "SAL_BASE_BRUT",
  "prorata_panier_transport": "PRORATA_HEURES",
  "retard_reduit_heures_presence": false,
  "taux_hs_jour": 1.50,
  "taux_hs_nuit": 2.00,
  "taux_hs_ferie": 2.00
}
```

| المعامل | القيم المقبولة | الافتراضي | مصدر الافتراضي |
|---|---|---|---|
| `base_iep` | `SAL_BASE_BRUT` / `SAL_BASE_APRES_ABSENCES` | `SAL_BASE_BRUT` | سائد في برامج القطاع الخاص |
| `base_pri` | نفسها | `SAL_BASE_BRUT` | اتساقاً مع IEP |
| `prorata_panier_transport` | `AUCUN` / `PRORATA_HEURES` / `PRORATA_JOURS` | `PRORATA_HEURES` | مؤكَّد بالسنتيم في كشفين مستقلين |
| `retard_reduit_heures_presence` | `true` / `false` | `false` | مؤكَّد ميدانياً |
| `taux_hs_*` | ≥ 1,50 | 1,50 / 2,00 | الحد القانوني الأدنى (م.32 ق.90-11) |

### 1.2.2 ثلاث قواعد إلزامية حول الاتفاقية

**1. الافتراض ليس صمتاً.** كل معامل اتفاقي يظهر في شاشة الشركة بشارة «اختيار اتفاقي — يُؤكَّد مع الزبون». ويمنع البرنامج توليد **أول كشف** للشركة حتى يصير `confirme_par_utilisateur = true`. هدف هذه القاعدة أن يسأل المستخدم زبونه بدل أن يخمّن.

**2. الاتفاقية تُصوَّر في كل كشف.** يُخزَّن `convention_version` داخل الكشف مثل `params_version` تماماً. إن غيّرت الشركة قاعدتها في مارس، تبقى كشوف فيفري قابلة لإعادة الطباعة كما صدرت بالضبط.

**3. ما لا يُفتح للتعديل إطلاقاً.** قاعدة عدم التقريب الوسيط (§5.4)، وكل ما يخصّ IRG وCNAS. هذه محرّك لا اتفاقية، ولا يجوز أن يظهر لها أي خيار في أي واجهة.

### 1.2.3 تنسيب السلة والنقل

```
heures_presence = heures_mois − heures_absence_irreguliere − heures_absence_justifiee
                  (بدون ساعات التأخّر إن كان retard_reduit_heures_presence = false)

montant = montant_mensuel × heures_presence / heures_mois
```

مؤكَّد بالسنتيم: 2 500 × 101,33 ÷ 173,33 = 1 461,52 · و 5 000 × 96 ÷ 173,33 = 2 769,28

### 1.2.4 منحة الأقدمية — تُقترَح ولا تُفرَض

**لا توجد قاعدة وطنية.** الكشوف الحقيقية تُثبت ذلك: نسبة 7,08% لأقدمية 9 سنوات وشهر · 4% لسنتين · 0% لسنة وشهر. لا صيغة تُنتج هذه الأرقام الثلاثة معاً، والنسبة تختلف حتى بين عاملين في **نفس** المؤسسة.

لذلك: **حساب الأقدمية آلي، واختيار النسبة يدوي.**

```
الأقدمية = (تاريخ الكشف − employe.date_entree) بالسنوات والأشهر    ← يحسبه البرنامج
النسبة المقترَحة:
    1) employe.taux_iep إن كانت مضبوطة                            ← تُستعمل مباشرة
    2) وإلا: عدد السنوات الكاملة × iep.taux_par_annee (1% افتراضياً)
    3) إن كانت الأقدمية < iep_anciennete_minimale_annees (1 افتراضياً) → 0%
```

الحقل **قابل للتعديل دائماً**، مع تمييز بصري بين «مقترَحة» و«معدَّلة يدوياً»، وزر عودة إلى المقترَح.

⚠️ **ممنوع تطبيق الأقدمية آلياً بلا عرض.** خطؤها صامت: نسبة 9% بدل 7,08% تعني فارقاً بأكثر من ألف دينار شهرياً برقم يبدو معقولاً تماماً. المكسب الحقيقي من الأتمتة هو **حساب مدة الأقدمية**، لا تحديد النسبة.

معاملان اتفاقيان يُضافان إلى §1.2.1: `iep_anciennete_minimale_annees` (افتراضياً 1) و`iep_taux_par_annee` (افتراضياً 0,01).

## 2. نموذج البيانات (Data Model)

### 2.1 الرُبريكة `Rubrique` — قلب النظام

كل سطر في كشف الراتب هو رُبريكة، ولها **خاصيتان إلزاميتان** لا يجوز أن تكونا فارغتين:

```python
@dataclass
class Rubrique:
    code: str              # ترميزك الداخلي (مثلاً "1010")
    libelle_fr: str
    libelle_ar: str
    sens: str              # "GAIN" | "RETENUE"
    mode: str              # "MONTANT" | "TAUX_SUR_BASE" | "QUANTITE_X_PU" | "FORMULE"
    base_calcul: list[str] # ex: ["SAL_BASE"] أو ["SAL_BASE","IEP"]
    cotisable: bool        # يدخل في وعاء CNAS ؟   ← إلزامي
    imposable: bool        # يدخل في وعاء IRG ؟    ← إلزامي
    regime_irg: str        # "BAREME" فقط في هذه النسخة (انظر 2.4)
    proratisable: bool     # يُقسَّم على أيام الحضور ؟
    depend_de: list[str]   # رموز الرُبريكات التي يجب حسابها قبل هذه
    ordre_affichage: int   # الترتيب داخل منطقتها فقط (لا يتجاوزها)
    # ⚠️ zone و ordre_calcul يُشتقّان آلياً — ممنوع إدخالهما يدوياً (انظر 2.3)
```

**قاعدة برمجية صارمة:** أي رُبريكة تُنشأ بدون تحديد `cotisable` و `imposable` صراحةً → ترفع `ValidationError` ولا تُحفظ. هنا يقع 90% من أخطاء الأجور والتقويمات الجبائية.

### 2.2 الجدول المرجعي الافتراضي (يُحمَّل عند إنشاء شركة جديدة)

| الرُبريكة | sens | cotisable | imposable | proratisable |
|---|---|---|---|---|
| الأجر القاعدي | GAIN | ✅ | ✅ | ✅ |
| الساعات الإضافية | GAIN | ✅ | ✅ | ❌ |
| منحة الأقدمية IEP | GAIN | ✅ | ✅ | ✅ |
| منحة المردودية PRI/PRC | GAIN | ✅ | ✅ | ✅ |
| منحة العمل بالتناوب (poste) | GAIN | ✅ | ✅ | ✅ |
| منحة الضرر/الخطر (nuisance) | GAIN | ✅ | ✅ | ✅ |
| تعويض العطلة المدفوعة | GAIN | ✅ | ✅ | ❌ |
| **منحة السلة (panier)** | GAIN | ❌ | **✅** | ✅ |
| **منحة النقل** | GAIN | ❌ | **✅** | ✅ |
| منحة السيارة | GAIN | ❌ | ✅ | ❌ |
| منحة المنطقة (zone) | GAIN | ❌ | ❌ | ✅ |
| المنح العائلية | GAIN | ❌ | ❌ | ❌ |
| المنحة المدرسية / الأجر الوحيد | GAIN | ❌ | ❌ | ❌ |
| مصاريف المهمة (بوثائق) | GAIN | ❌ | ❌ | ❌ |
| منحة ليلية | GAIN | ✅ | ✅ | ✅ |
| منحة إنابة / معلّم تمهين | GAIN | ✅ | ✅ | ✅ |
| اقتطاع أيام غياب | RETENUE | ✅ (سالب على الوعاء) | ✅ | — |
| اقتطاع ساعات غياب | RETENUE | ✅ (سالب على الوعاء) | ✅ | — |
| اقتطاع ساعات تأخّر | RETENUE | ✅ (سالب على الوعاء) | ✅ | — |
| اقتطاع تعاضدية (mutuelle) | RETENUE | ❌ | ❌ | — |
| اقتطاع CNAS 9% | RETENUE | — | — | — |
| اقتطاع IRG | RETENUE | — | — | — |
| تسبيق على الراتب | RETENUE | ❌ | ❌ | — |
| اقتطاع بحكم قضائي (opposition) | RETENUE | ❌ | ❌ | — |
| الاشتراك النقابي | RETENUE | ❌ | ❌ | — |

> **رُبريكتا الغياب بالساعات — الفصل حسابي لا إداري.**
> `اقتطاع ساعات غياب` يجمع كل أنواع الغياب (مبرر، غير مبرر، مغادرة) في رُبريكة واحدة: المعادلة واحدة والأثر واحد. برامج أخرى تفصلها لأغراض إدارية؛ نحن لا نفعل — سبب الغياب شأن صاحب العمل لا شأن مُصدِر الكشف.
> لكن `اقتطاع ساعات تأخّر` **يبقى منفصلاً إجبارياً**: ساعات الحضور المستعملة في تنسيب السلة والنقل (§1.2.3) تُطرح منها ساعات الغياب **ولا تُطرح منها ساعات التأخّر**. دمجهما يُنقص السلة والنقل خطأً (مثال مؤكَّد: 72 س غياب + 11,38 س تأخّر → حضور 101,33 لا 89,95 → سلة 1 461,52 لا 1 297,36).
> **المقامان مختلفان ولا يُحوَّل بينهما:** الأيام ÷ 30، الساعات ÷ 173,33. اليوم القانوني 5,78 س بينما يوم العمل الفعلي 8 س — فخصم يوم ≠ خصم 8 ساعات. استعمل ما أدخله المستخدم كما هو.

> السلة والنقل: معفاتان من CNAS (تعويضات ممثلة لمصاريف — الأمر 95-01) لكنهما **خاضعتان لـ IRG**. هذا الخطأ هو الأكثر شيوعاً في برامج الأجور الجزائرية.

## 2.3 بنية الكشف: الأسطر النظامية والمناطق (Zones)

### 2.3.1 الأسطر النظامية الخمسة — مقفلة

خمسة أسطر يولّدها البرنامج نفسه، لا يستطيع المستخدم حذفها ولا نقلها ولا تعديل قيمتها يدوياً (read-only):

| الرمز | السطر | المعادلة |
|---|---|---|
| **[A]** | `SALAIRE DE POSTE` — الأجر الخاضع للاشتراك | Σ المنطقة Z1 |
| **[B]** | اقتطاع CNAS 9% | [A] × 0,09 |
| **[C]** | **الأجر الخاضع للضريبة** | ( [A] − [B] ) + Σ المنطقة Z2 |
| **[D]** | **اقتطاع IRG** | `calcul_irg([C])` |
| **[E]** | الصافي للدفع | ΣZ1 + ΣZ2 + ΣZ3 − [B] − [D] − ΣZ4 |

🔒 **[C] و [D] متلاصقان إجبارياً.** يجب أن يمنع البرنامج إدراج أي رُبريكة بينهما، لأن IRG يُحسب من السطر الذي فوقه مباشرة.

### 2.3.2 المناطق الأربع — تُشتقّ آلياً

المستخدم **لا يختار موقع الرُبريكة**. يجيب فقط عن سؤالين (`cotisable` و `imposable`)، والبرنامج يضعها في منطقتها تلقائياً:

| المنطقة | الشرط | الموقع | أمثلة |
|---|---|---|---|
| **Z1** | `cotisable = true` | فوق [A] | الأجر القاعدي، IEP، المردودية، الساعات الإضافية، اقتطاع الغيابات (بإشارة سالبة) |
| **Z2** | `cotisable = false` و `imposable = true` | بين [B] و [C] | السلة، النقل، منحة السيارة |
| **Z3** | GAIN، `cotisable = false` و `imposable = false` | تحت [D] | منحة المنطقة، المنح العائلية، مصاريف المهمة |
| **Z4** | RETENUE غير CNAS/IRG | تحت [D] بعد Z3 | التسبيقات، الأحكام القضائية، الاشتراك النقابي |

```python
def zone_de(r: Rubrique) -> str:
    if r.sens == "RETENUE":
        # اقتطاع خاضع للاشتراك (غياب/تأخّر) → Z1 بإشارة سالبة،
        # لأنه يُطرح داخل [A] = ΣZ1 قبل حساب CNAS.
        return "Z1" if r.cotisable else "Z4"
    if r.cotisable:
        return "Z1"
    return "Z2" if r.imposable else "Z3"
```

**هذه الدالة هي جوهر التنظيم:** أي رُبريكة جديدة تُضاف مستقبلاً تجد مكانها الصحيح دون تدخّل بشري، ويستحيل أن تُوضع خطأً فوق [C] وهي غير خاضعة للضريبة.

### 2.3.3 الشكل النهائي للكشف

```

│       منحة الأقدمية 8% ...................  +3 600,00
│       منحة المردودية 15% .................  +7 290,00
│       ساعات إضافية (10 س × 1,5) ..........  +3 894,31
│       اقتطاع الغيابات .....................       0,00
├─ [A] SALAIRE DE POSTE .................... 59 784,31   🔒
├─ [B] اقتطاع CNAS 9% ...................... −5 380,59   🔒
├─ Z2 ─ منحة السلة (22 يوم × 250) .........  +5 500,00
│       منحة النقل .........................  +3 000,00
├─ [C] الأجر الخاضع للضريبة ................ 62 903,72   🔒
├─ [D] اقتطاع IRG .......................... −9 283,00   🔒
├─ Z3 ─ المنح العائلية (طفلان) ............     +600,00
├─ Z4 ─ تسبيق على الراتب ...................       0,00
└─ [E] الصافي للدفع ........................ 54 220,72   🔒
```

### 2.3.4 ترتيب العرض ≠ ترتيب الحساب

هذا فخّ يجب تجنّبه: منحة المردودية تُعرض بعد الأقدمية، وهي أيضاً **تعتمد عليها** في الحساب. لكن هذا التطابق مصادفة ولن يستمر مع رُبريكات مستقبلية.

لذلك يوجد ترتيبان منفصلان:

- **`ordre_affichage`** — يحدّده المستخدم داخل منطقته فقط. لا أثر له على النتيجة.
- **`ordre_calcul`** — يُشتقّ آلياً من `depend_de` عبر **ترتيب طوبولوجي** (topological sort). المستخدم لا يراه ولا يعدّله.

يجب أن يكشف البرنامج **الاعتماد الدائري** (A تعتمد على B و B تعتمد على A) ويرفض الحفظ.

### 2.3.5 مكسب هذا التصميم في الواجهة

عند إنشاء رُبريكة جديدة، بمجرد أن يضغط المستخدم مفتاح `خاضع للضريبة`، **يقفز السطر بصرياً إلى منطقته الجديدة أمام عينيه**. هذا تأكيد بصري فوري يمنع الخطأ قبل وقوعه، بدلاً من اكتشافه في تقويم جبائي بعد سنة.

## 2.4 نظام الاقتطاع الضريبي `regime_irg` — محجوز

كل رُبريكة تحمل خاصية ثالثة `regime_irg`، والقيمة الوحيدة المقبولة في هذه النسخة هي `"BAREME"` (تدخل الوعاء الخاضع للسلم التصاعدي).

القيمة `"TAUX_10"` — المنح المدفوعة بدورية غير شهرية (منحة مشروع، منحة سداسية) التي تخضع لاقتطاع محرِّر بنسبة 10% خارج السلم — **موجودة في النموذج ولكنها غير مدعومة**. يجب أن يرفضها البرنامج برسالة صريحة:

> «نظام الاقتطاع المحرِّر (10%) غير مدعوم في هذه النسخة.»

**لماذا نحجز مكانها الآن؟** لأن دعمها لاحقاً يعني **وعاءين ضريبيين منفصلين** وسطرَي IRG في الكشف. إن لم نحجز الخاصية اليوم، فإضافتها غداً ليست إضافة قيمة بل تفكيك لكل ما بُني فوق افتراض «وعاء ضريبي واحد»: التسلسل، الواجهة، القاعدة، والقالب المطبوع.

⚠️ إن دُعمت مستقبلاً، انتبه لقاعدة رصدناها في كشف حقيقي: عندما تكون المنحة قد خضعت لاشتراك CNAS، **يُعاد إدراج ما يقابل 9%** في الوعاء الخاضع للسلم حتى لا يُخصم الاقتطاع مرتين.

## 4. دالة IRG المرجعية

```python
from decimal import Decimal, ROUND_HALF_UP, ROUND_FLOOR

def arrondi_dizaine_inf(x: Decimal) -> Decimal:
    return (x / 10).to_integral_value(rounding=ROUND_FLOOR) * 10

def da(x) -> Decimal:                      # arrondi monétaire
    return Decimal(x).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)

def bareme_mensuel(assiette: Decimal, tranches: list) -> Decimal:
    """Barème progressif PAR TRANCHES — jamais un taux unique sur le total."""
    impot = Decimal(0)
    plancher = Decimal(0)
    for t in tranches:
        plafond = Decimal(t["plafond"]) if t["plafond"] is not None else None
        if plafond is None or assiette <= plafond:
            impot += (assiette - plancher) * Decimal(str(t["taux"]))
            break
        impot += (plafond - plancher) * Decimal(str(t["taux"]))
        plancher = plafond
    return impot

def calcul_irg(assiette: Decimal, cfg: dict) -> Decimal:
    p = cfg["irg"]

    # (a) arrondi de l'assiette à la dizaine inférieure
    R = arrondi_dizaine_inf(assiette) if p["arrondi_assiette_dizaine_inferieure"] else assiette

    # (b) exonération totale
    if R <= Decimal(p["seuil_exoneration"]):
        return Decimal("0.00")

    # (c) barème progressif → IRG brut
    irg_brut = bareme_mensuel(R, p["tranches_mensuelles"])

    # (d) 1er abattement : 40% DE L'IMPÔT (pas du salaire), borné 1000–1500 DA/mois
    ab = irg_brut * Decimal(str(p["abattement"]["taux"]))
    ab = min(max(ab, Decimal(p["abattement"]["min_mensuel"])),
             Decimal(p["abattement"]["max_mensuel"]))
    irg1 = irg_brut - ab

    # (e) 2e abattement (lissage) — bornes STRICTES des deux côtés.
    #     Art. 104 CIDTA : « revenus SUPÉRIEURS à 30.000 et INFÉRIEURS à 35.000 ».
    #     35 000,00 exactement est HORS lissage → calcul normal.
    liss = p["lissage_standard"]
    if Decimal(liss["borne_inf"]) < R < Decimal(liss["borne_sup"]):
        irg = irg1 * Decimal(str(liss["coef_a"])) - Decimal(str(liss["coef_b"]))
        return max(Decimal("0.00"), da(irg))

    return da(irg1)
```

### نقاط تنبيه للمبرمج

1. **`abattement` يُطبَّق على الضريبة، لا على الأجر.** كثير من المواقع والمنتديات تشرحها خطأً كـ «خصم 40% من الأجر» — النتيجة تكون خاطئة تماماً.
2. **الصيغة القديمة `IRG1 × (8/3) − (20000/3)` مهجورة**: كانت مُعايَرة على السلم السابق لقانون المالية 2022. لو استعملتها مع السلم الحالي تعطي نتائج سالبة على كامل الشريحة 30.001–35.000.
3. `max(0, ...)` إلزامي بعد التنعيم — الضريبة لا تكون سالبة أبداً.
4. استعمل `Decimal` وليس `float`. حساب النقود بـ float يولّد فروقات دينار في التصريح G50.

3. تطبيق التخفيض 40% على الأجر بدل الضريبة.
4. استعمال 20 000 دج كـ SNMG (قديم — أُلغي في 01/01/2026).
5. اعتبار «أول 4 ساعات إضافية بـ 50% والباقي 100%» — قاعدة فرنسية لا وجود لها في القانون الجزائري.
6. حساب IRG قبل خصم CNAS.
7. استعمال 26% كحصة المستخدم (الصحيح 25% + 0,5% خدمات اجتماعية = 34,5% إجمالي مع حصة العامل).
8. تخزين معاملات القانون داخل الكود بدل ملف إعدادات مؤرَّخ.
